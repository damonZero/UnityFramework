# 公共组件定制化解析使用文档

> 适用模块：`Json2Prefab` 管线（PSD → JSON → UGUI Prefab）
> 核心代码：`Json2Prefab\PrefabFactory\CommonPrefabPlugin\`

---

## 一、概述

公共组件在 PSD 中**以组（Group）的形式存在**，通过命名约定与预制体资产关联。导出时由 `Json2PrefabAssembleTool.CommonPrefabHandler` 实例化对应预制体，并交由 `Json2PrefabCommonPrefabPluginMgr` 做定制化解析。

本系统提供三大能力：

1. **递归复用内嵌公共组件**：外层大预制体（Z）内嵌子公共组件（A/B/C）时，直接复用其已有实例的定制化解析，不重复实例化。
2. **灵活布局容器**：通过 `XXX_容器` 命名约定，让**任意公共组件**自动获得"容器"能力，美术在 PSD 自由组装内容。
3. **公共组件缩放**：通过 `@Sxx` / `@sxx` 命名后缀，缩放公共组件根节点。

---

## 二、插件基类与接口

### 接口 `IJson2PrefabCommonPrefabPlugin`

| 成员 | 说明 |
|------|------|
| `IEnumerable<string> Names` | 公共组件名字（多个近似公共组件可用同一套处理逻辑） |
| `Json2PrefabEnum UseSelfPosition` | 位置是否使用预制体自身（`None`=PSD坐标 / `X`/`Y`/`XY`=固定） |
| `Json2PrefabEnum UseSelfSize` | 宽高是否使用预制体自身（`None`=PSD尺寸 / `Width`/`Height`/`WidthHeight`） |
| `bool IsInterruption` | 是否阻断当前节点的子节点生成（`true`=预制体已含全部内容） |
| `bool AutoReuseEmbedded` | 是否自动复用内嵌的公共组件实例 |
| `void CustomizedCheck(node, instance)` | 定制化解析逻辑 |

### 基类 `Json2PrefabCommonPrefabPluginBase`

**子类只需继承本类，必须覆写 `Names` / `CustomizedCheck`，其余成员提供默认实现可按需覆写。**

```csharp
public abstract class Json2PrefabCommonPrefabPluginBase : IJson2PrefabCommonPrefabPlugin
{
    public abstract IEnumerable<string> Names { get; }                    // 子类必须覆写
    public virtual Json2PrefabEnum UseSelfPosition => Json2PrefabEnum.None;
    public virtual Json2PrefabEnum UseSelfSize => Json2PrefabEnum.None;
    public virtual bool IsInterruption => true;
    public virtual bool AutoReuseEmbedded => true;                        // 默认复用内嵌子组件
    public abstract void CustomizedCheck(PsdNodeBase node, GameObject instance);  // 子类必须覆写
}
```

### 最小插件示例

```csharp
/// <summary>我的公共组件</summary>
public class Json2PrefabMyNode : Json2PrefabCommonPrefabPluginBase
{
    public override IEnumerable<string> Names => new[] { "MyNodePrefab" };

    public override void CustomizedCheck(PsdNodeBase node, GameObject instance)
    {
        // 定制化解析逻辑, 例如替换文本/图片
    }
}
```

> 注意：插件自动注册到 `_dictCommonPrefabPlugin`（通过反射扫描 `IJson2PrefabCommonPrefabPlugin` 子类）。**抽象基类不会被实例化**（`IsAbstract` 过滤）。

## 三、递归复用内嵌公共组件

### 场景

外层大预制体 Z 内嵌子公共组件 A/B/C，且 **A/B/C 在预制体内已是实例**（可被改名）。需要让 A/B/C 复用各自的定制化解析，**不重复实例化**。

```
Z (公共组件预制体)
├── A (内嵌实例, 可能已改名)
├── B (内嵌实例)
└── C (内嵌实例)
```

### 机制

`CustomizedCheck` 处理完当前公共组件后，自动调用 `ProcessEmbeddedCommonPrefabs` 遍历其 PSD 子节点：

1. 子节点是 **Group** 才可能是公共组件（其他类型跳过）
2. 子节点匹配到插件 → `FindEmbeddedInstance`（改名免疫）→ `RunPluginReuse` 复用
3. `RunPluginReuse` 内再递归其子孙公共组件（**递归自然驱动**）
4. 子节点是普通分组 → 沿名字 `Find` 定位继续深入

```
CustomizedCheck(Z)
└─ ProcessEmbeddedCommonPrefabs(Z)
     ├─ 子节点A(公共组件) → RunPluginReuse(A) → pluginA.CustomizedCheck(A)
     │    └─ ProcessEmbeddedCommonPrefabs(A)  ← A内嵌套组件递归
     ├─ 子节点B(公共组件) → RunPluginReuse(B)
     └─ 子节点"普通分组" → Find深入
```

### 改名免疫

复用匹配使用 `PrefabUtility.GetCorrespondingObjectFromOriginalSource` 取**来源预制体资产名**，**改实例名不影响匹配**。

### 开关控制

- **`AutoReuseEmbedded`（默认 `true`）**：需要复用内嵌子组件时保持默认。
- **覆写为 `false`**：当插件**自行管理子节点生成**（如列表、页签）时，避免与复用逻辑叠加。

```csharp
public override bool AutoReuseEmbedded => false;   // 列表/页签等自行管理子节点的插件
```

### 约定

**Z 即使没有自己的定制化解析，也必须写一个空壳插件**（只声明 `Names` + 空 `CustomizedCheck`），就为了触发内嵌子节点的递归解析。

## 四、灵活布局容器

### 场景

预制体内有**容器节点**，内容不确定，需要美术在 PSD 端自由组装（可放已有的公共组件或非公共组件），导出时自动填充。

> **容器是否使用布局由需求决定，非强制**：
> - 预制体容器节点带 **LayoutGroup** → 子节点由布局接管自动排列
> - 预制体容器节点是**纯空节点** → 子节点按 PSD 位置摆放（依赖美术摆放）

### 命名约定

| PSD 组名 | 预制体节点名 | 说明 |
|----------|-------------|------|
| `奖励_容器` | `奖励_容器` | 普通容器 |
| `标题_容器` | `标题_容器` | 普通容器 |
| `奖励_容器1` | `奖励_容器1` | 同类型多个容器，序号区分 |

- **后缀 `_容器` 是识别标记**，代码 `EndsWith("_容器")` 自动识别。
- **PSD 与预制体节点同名**匹配。
- 下划线避免误伤普通"XX容器"命名。

### 使用步骤

1. **预制体端**：在公共组件预制体内放容器节点，命名为 `奖励_容器`（是否挂 LayoutGroup 按需求）。
2. **PSD 端**：在公共组件组内建同名子组 `奖励_容器`，自由摆放内容（公共组件或普通组/图片/文本）。
3. **导出**：`ProcessEmbeddedCommonPrefabs` 识别 `_容器` 后缀 → `FillContainer` 填充。

### 机制

```
ProcessEmbeddedCommonPrefabs(Z)
└─ 子节点"奖励_容器" → EndsWith("_容器") → FillContainer
     └─ 找预制体同名"奖励_容器" → AssembleRecursion(子节点)
          ├─ ctnSquare__0 (公共组件) → 实例化 + 定制化解析 + 递归其容器  ← 自动
          └─ myGroup (普通组) → 生成普通节点
```

- 容器内每个子节点 `AssembleRecursion` 生成到容器下，位置按 PSD 数据设置。
- **容器带布局**：LayoutGroup 接管排列，覆盖位置；**容器纯空节点**：保留 PSD 位置，依赖美术摆放。
- 容器内公共组件会自动实例化并走定制化解析（含递归）。
- **布局控制子节点宽高时的尺寸保护**：若容器带 `HorizontalOrVerticalLayoutGroup` 且 `childControlWidth/Height=true`，对**非公共预制体**子节点自动添加 `LayoutElement`，并按 PSD 尺寸设置 `preferredWidth/preferredHeight`，避免布局把子节点宽高归零（公共预制体自身已有布局处理，不额外添加）。

### 关键点

- **任意公共组件**（只要 `AutoReuseEmbedded=true`）都自动支持容器，**无需改继承或代码**。
- 新增容器 = 在 PSD 加 `_容器` 组 + 预制体加同名节点，**无需改代码**。
- 多个容器：`奖励_容器`、`标题_容器` 或 `奖励_容器1`/`奖励_容器2`。

## 五、公共组件缩放

### 命名约定

在公共组件名后追加 `@Sxx` 或 `@sxx`（S 不分大小写，xx 为百分比整数）：

```
MyNode@S70      → 缩放 70%
CmnBtnClose__0@S80  → 缩放 80% (含状态后缀)
```

### 机制

`CreateGroup`（`Json2PrefabFactory`）解析 `@Sxx`：

```csharp
var scale = Psd2UguiTool.ParseCommonPrefabScale(node.name);   // @S70 → 0.7
if (scale.HasValue)
    node.name = Psd2UguiTool.StripCommonPrefabScaleSuffix(node.name);   // 剥离标记
// ... 实例化后 ...
commonPrefab.transform.localScale *= scale.Value;   // 累乘, 保留预制体原缩放
```

- **只设置根节点缩放**，组件内部 UI 缩放由预制制作时决定。
- **累乘**（`*=`）：保留预制体自身的缩放值。
- 应用后剥离 `@Sxx` 后缀更新 `node.name`，后续逻辑（匹配、`AdjustName` 生成节点名）不再关心该标记。

### 工具方法（`Psd2UguiTool`）

| 方法 | 说明 | 示例 |
|------|------|------|
| `ParseCommonPrefabScale(name)` | 解析缩放百分比 | `CmnBtnClose__0@S70` → `0.7` |
| `StripCommonPrefabScaleSuffix(name)` | 剥离缩放标记段 | `CmnBtnClose__0@S70` → `CmnBtnClose__0` |
| `GetCommonPrefabName(name)` | 提取公共组件名 | `CmnBtnClose__0` → `CmnBtnClose` |
| `GetCommonPrefabNameSuffix(name)` | 提取状态后缀 | `CmnBtnClose__one@S70` → `one` |

> 正则 `@[Ss]\d+` 精准匹配 `@S`/`@s` + 数字，不分大小写，只删缩放标记段。

## 六、整体解析流程

```
PSD 节点 Z (公共组件)
└─ CreateGroup(Z)                          [Json2PrefabFactory]
     ├─ 解析 @Sxx 缩放 → 剥离 → 应用根节点缩放
     └─ CommonPrefabHandler(Z)             [Json2PrefabAssembleTool]
          ├─ 匹配预制体 GUID → 实例化
          └─ CustomizedCheck(Z)            [Json2PrefabCommonPrefabPluginMgr]
               ├─ SetSize/SetPos(插件UseSelf)
               ├─ plugin.CustomizedCheck(Z)
               └─ AutoReuseEmbedded → ProcessEmbeddedCommonPrefabs(Z)
                    ├─ _容器 后缀 → FillContainer (AssembleRecursion生成)
                    ├─ 公共组件子节点 → RunPluginReuse (复用定制化解析)
                    ├─ 普通分组 → Find深入
                    └─ 非Group → 跳过
```

## 七、常见问题

### Q1: Z 没有自己的定制化解析，也要写插件吗？
**要。** 写一个只声明 `Names` + 空 `CustomizedCheck` 的空壳插件，`AutoReuseEmbedded` 默认 `true` 会触发内嵌子组件（A/B/C）的递归解析。

### Q2: 什么插件要覆写 `AutoReuseEmbedded => false`？
**自行管理子节点生成的插件**（列表 `lvVertical`、页签 `TabPage`、弹窗 `PopUpPanel`、奖励列表 `AwardList` 等）。它们内部用 `AssembleRecursion` 生成子节点，若再复用会重复处理。

### Q3: 容器里能放公共组件吗？
**能。** `FillContainer` 对容器内子节点 `AssembleRecursion`，公共组件会实例化并走定制化解析（含递归）。

### Q4: 容器识别会误伤普通"XX容器"节点吗？
**不会。** 约定是下划线前缀 `_容器`（`XXX_容器`），普通中文名"背景容器"等不带下划线，`EndsWith("_容器")` 不会匹配。

### Q5: 内嵌子组件能带缩放标记吗？
**不能/不需要。** 缩放只作用于**根节点**（`CreateGroup`），内嵌子组件（复用路径）按预制体内部布局，不处理缩放。

### Q6: 预制体 RectTransform 用了 stretch 锚点，导出会被 PSD 覆盖吗？
**不会。** 尺寸设置（`SetWidthHeightByNode` / `SetSizeBySelfLockEnum`）与位置设置（`SetPositionByNode`）均已做**按轴 stretch 感知**：

- 某轴为 **stretch**（`anchorMin != anchorMax`）→ 该轴的锚点、尺寸、位置均保留预制体自身，**不覆盖**，拉伸效果生效。
- 某轴为**点锚点**（`anchorMin == anchorMax`）→ 正常用 PSD 宽高/位置覆盖。

因此 stretch 预制体（如铺满父节点的背景、面板底图、底部按钮栏 `CmnBottomButtons`）无需特殊处理即能保持拉伸，也无需额外覆写 `UseSelfPosition`。
